# 05 · 绝区零「Fairy」视觉参考系实测报告

> **调研对象**：HoYoverse《绝区零》（Zenless Zone Zero）中的 AI 助手「Fairy」及其外延视觉系统——包含 Fairy 观测日志页、AI 助理程序活动页、功能菜单（Function Menu）主题皮肤群、器材/装备界面、Inter-Knot（绳网）终端与公告、Hollow Zero 地图 UI、Phantom Terminal 终端、章节磁带封面、Fairy 头像图形。
> **目的**：为「ASTRA 观测台」提取**"AI 助手人格化 HUD"** 的可迁移机制。只借机制，不复制皮肤；最终产品自绘。

> **证据等级**：`【实测】`＝工具量化或标尺测量；`【目视】`＝看图可确认；`【推测】`＝反推，需实机验证。

> **⚠ 版权**：全部图像版权归 HoYoverse / miHoYo 所有，仅作仓库内研究凭证，不得进入最终构建、不得再分发。Fairy 的角色形象、台词、Inter-Knot / N.E.P. 等专名一律不得出现在产品中。

## 0 结论摘要（先读这段）

1. **Fairy 的"人格色"是蓝，不是青。** Fairy 头像（`zzz_16`）的主色是 `#3245e8` 12.8% / `#1f2d7c` 12.7% / `#1e488a` 11.4%，`meanSat 59.3%`【实测】——这是全 ZZZ 素材里饱和度最高的一张。青绿（`#44b8b5`、`#029e8e`）属于 **Inter-Knot / 绳网系统 UI** 与观测日志页，不是 Fairy 本体。→ **"AI = 蓝、系统 = 青"这条双色分工是可迁移的核心结论**。
2. **ZZZ 的 UI 骨架是"黑外壳 + 单色场 + 巨大描边字 + 胶囊标签"，不是"全息 HUD"。** 功能菜单（`zzz_03/04/05/06/22`）是**近黑哑光壳 + 3 列图标网格**，几乎无文字标签；海报（`zzz_08`）是**青绿平涂 + 巨字 + 网点阴影 + 黑胶囊**；器材界面（`zzz_07`）是**纯黑硬件径向盘**。所谓"科技感"来自**高对比排版 + 材质拟物**，不是半透明光效。
3. **Fairy 的图形语言 = 同心虹膜环 + 扫描线 + 一颗偏移的珠光点。** 头像（520×520）可量：外白环半径约 96% 画幅、内有一圈带 4 个缺口的"光圈叶片"环（半径约 67%）、再内一圈奶油亮环（半径约 44%）、中心深蓝核心、右下角一颗偏移的珍珠白圆点（半径约 5.4%，偏离中心约 15°）【目视+标尺】。整套只有 3 种元素（环、缺口、点），**极易自绘**。
4. **配色是"大面积黑 + 一块青 + 一点黄/红"的三段式。** 黑：`#000000` 28.9%（器材界面）、`#0a0a0c` 83.4%（Hollow 线稿地图）；青绿：`#44b8b5` 21.6%（日志页）、`#029e8e` 17.3% + `#01998a` 12.5% + `#019b8c` 9.6%（绳网海报，合并约 39%）；黄：`#f9d372` 14% / `#e5c053` 8.9%；红：`#c20806` 6.2%（磁带封面）【实测】。
5. **"密集微标签"是真的存在，且可量化**：`zzz_08` 海报在 1242×699 里塞了 6 层文字（巨标→副标→胶囊→期号→细字页脚→微缩伪文本），最小字号约 10px @1242 宽（≈ 0.8% 画幅宽）；`zzz_18` 手机 UI 里还有 6–8px 级微标签【目视估算】。→ 我们可借"层数"，**但字号下限必须抬到 10px 以上**。
6. **可迁移度最高的 3 个机制**：① 双色人格分离（AI=蓝 / 系统=青）+ 大面积黑外壳；② 胶囊标签系统（icon + 大写 label + 可嵌搜索/状态）；③ 同心虹膜环作为"AI 存在"的统一图形母题。
7. **必须避开的皮**：ZZZ 的涂鸦/破损海报字体与 logo、Fairy 的角色立绘与台词语气、Inter-Knot / N.E.P. / H.S.O.S.6 等专名、磁带封面美术、`#029e8e` 这类精确品牌青、以及"CRT 电视噪点 + 故障抖动"整套效果（做不好会像廉价赛博朋克）。

## B 逐图观察

### B.1 Fairy 直接相关（3 张）

**01 · Fairy 观测日志（Biological Observation Log）** — 构图：整屏是一块**薄荷青平涂场**（`#44b8b5` 21.6%），上面"贴"了一个**圆角矩形窗口**，窗口有 6–8px 白描边 + 2px 黑外框 + 圆角约 32px。窗口内部是 Q 版角色的平涂插画（室内柜台场景），窗口中还有二级 UI：左上角小地图/圆形 HUD、角色头顶小标签、室内贴纸。窗框顶部：左侧一条**黄色标签条**（`#e1c85f` 6.6%）印着极小的重复装饰字与 `H.A.N.D.` 标题；右上角三个黄色圆点（省略号）+ 两个小方块图标；右下角一个**白色胶囊**（内含放大镜 + `H.S.O.S.6` 宽字距标签）；左下角 ZZZ logo 小标。整体只有 4 种色：青场、白框、黑线、黄条【目视】。**这张图是"内容卡片 + 截图装裱"的极佳样本：它把游戏画面包装成"一本观测日志里的插图"，而不是直接给你一个 HUD。**

**配色用途逻辑（为什么这样分）**：
- **黑 = 世界（新艾利都的夜/电视/硬件）**：ZZZ 的 UI 外壳几乎全是近黑哑光，米白只用于文字与纸张。→ 我们的界面应当**以暗底为主场，青/蓝/黄/红都是"点亮"**。
- **青 = 系统在说话，蓝 = AI 在说话**：这是最有价值的发现。观测日志（青）讲"我们记录了它"，Fairy 头像（蓝）讲"它本身"。→ 我们可以照搬这个分工：**青色用于数据通道/系统消息，蓝色只用于 AI 助手本体与它的输出**。
- **黄 = 活动/提醒**：ZZZ 用黄表示"有事情发生"（更新、活动、奖励），比红色更友好。→ 我们的"提示级"用黄，"错误级"才用红。
- **红 = 章节/危险**，且总是极小面积（6.2% 已是全组最大）。
- **黑 + 米白 = 画册/磁带/封面**：这是 ZZZ 的"收藏品"美学，与屏内 UI 的青色形成对比。

### C.4 材质与光感的量化

- **扫描线**：Fairy 图形背景的水平扫描线，线距约 **4px @520px 画幅**（≈ 0.77% 画幅高），不透明度目视 < 10%；Hollow UI 与手机 UI 也有类似纹理。
- **网点（halftone）**：海报巨字的阴影是**网点**而非纯色（点径目视 2–3px，密度约 50%）。这是"印刷感"的来源，不是渐变。
- **硬阴影**：海报字与卡片使用**无模糊、固定偏移**的硬阴影（约 8–14px 偏移，@1242 宽画幅）；不是柔和投影。
- **发光**：Fairy 白环有轻微外发光（目视半径约 12px、强度低）；霓虹青 `#00e5d8` 用于细线而非大面。

## D 字体与排版

### D.1 可确证的事实

1. **超浓缩大写 grotesque**：`THE NEWS`、`INTER-KNOT MAINTENANCE NOTICE`、`VOL.005` 都是极高 x-height、极窄字宽、全大写的展示字体；字距紧（目视 -2%~-3%），笔画粗【目视】。
2. **"描边 + 网点阴影 + 叠压"三件套**：奶白填充 → 黑描边（约 14px @1242 宽）→ 网点/硬阴影；字母互相叠压、部分标签带 **-8° 倾角**。这是"街头海报/贴纸"工艺【目视】。
3. **字号层级跨度极大**：`THE NEWS` 约 150px → `INTER-KNOT MAINTENANCE NOTICE` 约 72px → 胶囊内文字约 30px → `VOL.005` 约 54px → 页脚细字约 10px。**最大/最小 = 15×**【实测估算】。
4. **胶囊内文字用宽字距**（约 +5%），与巨字的紧缩形成对比，这是"同一张图里两种排版性格"的手法【目视】。
5. **功能菜单几乎无文字**：`FUNCTIONS` 一个标题 + 图标，其余全靠图标识别；字体是无衬线 grotesque，宽字距约 +8%【目视】。
6. **微标签确实存在**：手机 UI 与观测日志里的辅助文字最小约 6–8px（按画幅换算）【目视估算】。

### D.2 推测（需二次验证）

| 项目 | 推测 | 依据 | 风险 |
|---|---|---|---|
| 海报展示字体 | 类似 Druk Condensed / Anton / Bebas Neue 一类的浓缩 grotesque，或官方定制的街头风字 | 极窄 + 极高 x-height + 全大写 | 可用开源 Bebas/Anton 近似，但**不要再叠加描边网点**到"像 ZZZ"的程度 |
| 正文/UI 字体 | DIN / TT Norms / Roboto 一类中性 grotesque | UI 小字笔画匀称 | 选开源 DIN 替代（如 Barlow / IBM Plex Sans） |
| 手写/涂鸦字 | 官方定制 | `ASSISTANT PROGRAM`、箭头、贴纸上的手写感 | 不可复刻；要做"手写感"必须自己写一套 |
| CJK 字体 | 思源黑体 / 阿里巴巴普惠体一类 | 游戏内中文界面 | 未确证 |

### E.4 边缘处理与图标语言

- **圆角**：内容卡 32–40px；图标格 28px；胶囊全圆角；芯片/贴纸为**不规则多边形**（手撕边）。
- **描边**：内容卡 = 白 6–8px 内描边 + 黑 2px 外描边；图标 = 单色线稿（约 2.5px @64px 图标）；文字 = 黑 14px 外描边。
- **硬阴影**：卡片与字使用**无模糊、固定偏移**的硬阴影，偏移方向统一（右下）。
- **图标语言**：以"物件/动作"的剪影为主（锁、放大镜、齿轮、相机、球），单色线稿、统一线宽、圆头端点。
- **网点/抖动**：作为"印刷感"纹理层，出现在阴影、分隔条、贴纸上。

## F 动效与转场语言

> ⚠ 本节**没有录屏证据**（Fairy 本体 HUD 的一手视频未取得），以下为**基于静态图的工艺推断**，全部 `【推测】`，实现前需实机验证。

1. **开机自检（Fairy 风格）**`【推测】`：由 Fairy 图形的构造推断，最自然的自检动画是"**虹膜环逐层合拢**"——外白环先出现（描边绘制 240ms）→ 4 个缺口叶片旋转闭合（400ms）→ 奶油环亮起（200ms）→ 中心珠光点浮现（200ms，带一次 1.2× 缩放回弹）→ 背景扫描线从上往下刷过（600ms）。总计约 **1.6s**，可作为首屏序列。
2. **扫描线**`【推测】`：Fairy 图形背景的 4px 扫描线在动态中通常是**缓慢下移**（周期 6–10s，位移 = 线距的整数倍，避免抖动），不透明度 5–10%。
3. **台词化播报**`【推测】`：ZZZ 的文本呈现是"逐字打字 + 偶尔整句弹出"；建议节奏 **28–36ms/字**（中文）、整句进入用 120ms 向上位移 8px + 淡入；一句话结束后 1.2s 自动收起。
4. **贴纸/卡片弹入**`【推测】`：硬阴影 + 圆角卡片的入场通常带 **-4° 旋转 + 从 0.9 缩放到 1.0 + 位移 12px**，时长 **220–280ms**，ease-out-back（轻微 overshoot，幅度 ≤ 6%）；这与"印刷贴纸"的物理感一致。
5. **径向盘选择**`【推测】`：6 槽盘的交互通常是"旋转盘面 + 当前槽放大 1.08 + 状态灯变色"，旋转 180–260ms，用 cubic-bezier(0.2, 0.8, 0.2, 1)。
6. **故障/异常**`【推测】`：Hollow Zero 的紫绿硬边几何暗示"片段位移"而非全屏噪点：建议用 **3–5 条 1–2px 的水平切片错位（±6px）+ 60–120ms 的重复 2 次**，绝不做全屏随机噪点。
7. **禁用**：不要用"全屏 CRT 开机 + 长雪花噪点 + 持续抖动"。这是最容易被识破的廉价赛博朋克模仿；ZZZ 本人的画面里**没有**这套东西（它是印刷/电视卡带美学，不是 CRT 故障美学）。

## H 3 条可直接落地的设计规则

### H-1 五色语义 + 面积预算（照抄结构，不照抄色值）

- **依据**：ZZZ 的用色可以严格按语义归类（C.3），且每类在单图里的占比有实测上界：系统青 21.6%（UI 图）/ 39%（海报，例外）；AI 蓝 12.8%+12.7%+11.4%（图形专图）；事件黄 8.9%；危险红 6.2%（最大）；外壳黑 22.7%–83.4%【实测】。
- **落法**（建议值，配色自定）：
  - **外壳黑**（`#0a0a0c` 一类的近黑）作大面积底：**≥ 50% 视口**；
  - **系统色**（青系）**12–20%**，用于数据通道、系统消息、进度；
  - **AI 色**（蓝系）**≤ 8%**，只用于 AI 助手的输出与存在标记；
  - **事件色**（黄系）**≤ 6%**，只用于"有新事件/待处理"；
  - **危险色**（红系）**≤ 3%**，只用于错误与不可逆操作。
- **验收**：任意截图跑 `palette.py`，若"AI 色"排进前 3 主色，说明超预算（原图里 Fairy 蓝只在"专图"中当主色，普通界面里从不如此）。

### H-2 状态胶囊：高 = 容器高 10%，全圆角，内文字 = 胶囊高 42%，+5% 字距

- **依据**：`zzz_08` 实测胶囊高 72px / 画幅高 699px = 10.3%，胶囊内文字 30px / 72px = 41.7%，字距目视 +5%，圆角为全圆（半径 = 高/2），内 padding-x ≈ 40px（≈ 55% 高）【实测】。
- **落法**：`height = 40px`（若容器高 400px）→ 圆角 20px、字号 17px、内边距 22px、图标 20px、字距 `letter-spacing: 0.05em`；胶囊内多段信息用 **1px 分隔线**（`rgba(255,255,255,0.25)`）分隔，分隔线左右各 8px 空隙。
- **禁忌**：胶囊内不要放两行文字（原图所有胶囊都是单行）；不要把胶囊做成"按钮"（它首先是**状态标签**，其次才是可点）。

### H-3 卡片装裱：圆角 32px + 白 6px 内描边 + 黑 2px 外描边 + 硬阴影 offset(8,8) 0 blur

- **依据**：`zzz_01` 的观测日志窗口：圆角约 32px @1920 宽（1.7%），白描边 6–8px，黑外框约 2px，硬阴影向右下偏移约 8–14px 且**无模糊**；`zzz_08` 的巨字与卡片共用同一套硬阴影逻辑【目视+标尺估算】。
- **落法**：`border-radius: 32px; box-shadow: 0 0 0 2px #000, 8px 8px 0 rgba(0,0,0,0.85);` 内层用 `inset 0 0 0 6px #fff` 做白描边；内容区与描边之间留 16px 内边距。
- **禁忌**：不要用柔和投影（`blur > 0`）——ZZZ 的物理感来自"印刷/贴纸没有软阴影"；也不要在卡片上叠网点纹理（那是海报层的工艺，混用会脏）。

## I 与 ASTRA 产品的关联

### I.1 开机序列 → Fairy 虹膜自检（最强映射）

- **图形母题**：自绘一套"同心环 + 4 缺口 + 偏移珠点"的 ASTRA 标记（**不要**用 Fairy 的环径比与蓝色渐变），它同时是 logo、加载态、AI 状态指示器。
- **序列**（约 1.6–2.0s）：① 外环描边绘制 240ms；② 缺口叶片闭合 400ms；③ 内环亮起 200ms；④ 珠点浮现 + 1.2× 回弹 200ms；⑤ 扫描线自上而下刷过一次 600ms；⑥ 出现第一行 AI 播报文字（打字机 30ms/字）。
- **与星铁方案的差异**：星铁的开机是"纸/书"（撕纸 + 书写），ZZZ 的开机是"设备/环"（虹膜 + 扫描）。ASTRA 可以**二选一**或"先环后纸"：环代表"本机系统已连接"，纸代表"开始记录"。建议组合但控制总时长 ≤ 2.5s。

### I.2 告警 → 黄/红胶囊 + 单点

- **提示级**：黄胶囊（H-2 规格）+ 一个 6px 琥珀点（借 `zzz_07` 的单 LED），不闪烁、不弹窗。
- **危险级**：红胶囊 + 细红边（2px）+ 一次 60ms 的水平切片错位（借 F.6，且只做一次）。**绝不整屏变红**（原图红色最大只占 6.2%）。
- **"异常/数据破损"**：如果要表达"某个 agent 的数据流异常"，用紫色（`#7022ff` 那一族的语义）+ 硬边几何切片，而不是噪点。

### I.3 事件账本 → 双层结构（系统青 / AI 蓝）

- **系统层**（青色）：会话开始、文件变更、工具调用、耗时/Token 统计——**机器事实**。
- **AI 层**（蓝色，≤ 8% 面积）：助手说了什么、做了什么判断、播报——**人格输出**。
- 两层用**同一条时间轴**，靠颜色区分"谁在说话"。这正是 ZZZ "青=系统、蓝=AI" 的直接映射，且能解决"数据流和 AI 旁白混在一起"的可读性问题。
- 条目形态：胶囊（状态）+ 卡片（内容）+ 硬阴影（层级），不要用表格线分隔（ZZZ 没有横线表格的语言）。

### I.4 星图 → 6 槽径向盘 / 同心环

- 借用 `zzz_07` 的构图：**中心 = 调度器/hub；6 个环绕槽 = 6 组 agent**；每个槽有自己的小环与刻度；整个盘缓慢自转（周期 60–120s，极慢，只作"活着"的暗示）；**状态灯只用一个**（全局健康度），不每个槽都闪。
- 若 agent 数量 > 6：**嵌套一层**（槽内再分 3 个小弧），不要扩成 12/18 个槽（超过 8 个在盘上就失去"对称感"）。
- 键盘/无鼠标场景：盘可切换为 3 列卡片网格（借 E.2），保持同一套状态色。

### I.5 仪表盘 → 手机壳/图标矩阵

- **功能菜单范式**（E.2）适合"入口型"面板：每个 agent 一张 176px 圆角卡片，图标 + 状态灯 + 一行 12px 名称（**必须补文字**，ZZZ 的零文字在小屏上可用，在大屏仪表盘上会造成识别困难）。
- **主题皮肤变量化**（B.2 的发现）应工程化：`--bg / --panel / --system / --ai / --event / --danger` 六个 token 驱动全站配色，方便后续换肤。

### I.6 AI 助手播报（人格化）

- ZZZ 的 AI 呈现是**玩具/贴纸式**而非冷峻全息：短句 + 语气词 + 括号注释 + 手绘箭头（`zzz_08` 页脚有手绘箭头与气泡）。
- 建议：AI 播报文本 ≤ 2 行 × 22 字；句式"动作 + 结果 +（补充）"；语气可温和但不卖萌；**每次播报后 1.2s 自动收起**，不占用常驻空间。
- **不可做**：不要给 ASTRA 的 AI 起名/立绘/口癖去模仿 Fairy（角色 IP 风险 + 会显得像 cosplay）。
